# figmobil

Исходники: [cj-isus/figmobil](https://github.com/cj-isus/figmobil) · [скачать исходники ZIP](https://github.com/cj-isus/figmobil/archive/refs/heads/main.zip). Windows-сборка создаётся командой проверки ниже. Публикация готового архива в [Releases](https://github.com/cj-isus/figmobil/releases) пока не завершена; локальный архив находится в `dist/figmobil-windows-x64-preview.zip`.

Локальное Windows-приложение для ручного зашифрованного обмена кодом через текстовый слой Figma **без плагина**. На каждом ноутбуке выбирается один собственный проект; входящие версии и общая база управляются приложением. Диагностическое сравнение локальных папок сохранено в раскрываемом разделе.

Статус — локальная предварительная версия по D-16. Настройка пары, age/Ed25519/Windows DPAPI, части, общая база, предпросмотр и применение реализованы и проверены на искусственных файлах. Общая проверка и сборка: 10/10 групп PASS. Обмен через настоящий холст Figma, полный браузерный сценарий и две целевые машины ещё не приняты; [актуальные результаты](docs/STATE.md).

Основной сценарий — разработка с одной стороны, ручной merge с коллегами на другой и обратная отправка через Figma. Нет постоянного наблюдения, фоновой отправки или автоматического возобновления.

В первой версии поддерживается только совместимая политика Git без преобразований checkout. `autocrlf`, преобразующие attributes/filters и неизвестные правила останавливают применение; программа не меняет Git config и не нормализует файлы. Нужный реальный состав проекта и исключения согласовываются явно — большой dump не пропускается автоматически.

## Запуск

Запустите `dist/figmobil.exe` и откройте в браузере адрес из окна приложения. Второй процесс на устройстве блокируется, чтобы не разделять квоту. Для остановки используйте Ctrl+C; приложение дожидается завершения остановленных операций.

На целевом ноутбуке используются exe, существующий браузер и Figma Desktop. В Git-рабочих копиях используется уже имеющийся Git только для чтения эффективных config/attributes и режимов index. Git remotes, hooks, filters и код переносимого проекта не запускаются. Wails, WebView2, Node.js, Go, age.exe и Figma-плагин для запуска не устанавливаются автоматически.

1. На A выберите собственную папку, имя проекта/ноутбука и исключения; создайте приглашение, затем нажмите «Выдать следующую часть».
2. Перенесите текст в текстовый слой Figma. На B скопируйте именно содержимое слоя и примите приглашение со своей локальной папкой.
3. Верните ответ B → Figma → A. Сверьте одинаковый код непосредственно на двух экранах figmobil, подтвердите и обменяйтесь подтверждениями через Figma.
4. Явно экспортируйте начальную версию. На B добавьте части, покажите план и подтвердите применение. Существующие отличающиеся файлы без общей базы не затираются.
5. Верните подтверждение применения через Figma. Последующие изменения передаются теми же кнопками в обе стороны. При ручном слиянии используйте отдельный экспорт фактического результата.

Каждая часть выдаётся отдельно по кнопке, максимум 250 000 байт и не чаще раза в 3 секунды; все проекты/направления/повторы/подтверждения используют общую квоту до 5 000 000 байт за любые 60 секунд. Таймер ничего не отправляет. Фактическая вместимость текстового слоя пока не измерена; внутренний сетевой трафик Figma приложением не регулируется.

Ключи и состояние хранятся отдельно от проекта в `%LOCALAPPDATA%\figmobil`, защищены DPAPI текущего пользователя Windows. Скопировать exe на другой ноутбук можно; копирование локального состояния не заменяет создание его собственной пары ключей и сверку устройств. После прерывания записи интерфейс требует явного восстановления.

## Возможности

- Приглашение, сверка устройств, зашифрованные подписанные пакеты и явное подтверждение точной принятой версии.
- Отдельные выдача частей, импорт, предпросмотр, применение и обратная отправка результата ручного merge.
- Сравнение исходных байтов, размеров и метаданных; диагностика EOL/BOM без нормализации.
- Различение входящих и локальных правок при наличии общей базовой копии.
- Явные конфликты и отсутствие файла без автоматического удаления.
- Запуск по кнопке, отмена и защита от повторного запуска.
- Исключение служебных каталогов, секретных имён и ссылок; ограничения объёма чтения.
- Локальный интерфейс на `127.0.0.1` с ключом текущего сеанса и проверкой Origin/Host.

Подробности обмена — [TRANSPORT](docs/TRANSPORT.md), диагностики папок — [локальный компонент](docs/LOCAL-COMPONENT.md).

## Разработка и проверки

Для разработки нужны Go >=1.25 и Node.js >=22.13; зависимости закреплены в `go.mod`/`go.sum`. Криптографические зависимости и границы их проверки — [DEPENDENCIES](internal/secure/DEPENDENCIES.md). При передаче бинарника сохраняйте `THIRD-PARTY-NOTICES.txt` из dist.

```powershell
node scripts/project/verify.mjs
```

Команда выполняет 10 групп: обвязка, существующий/новый UI, Go tests/vet/format и сборка Windows exe. Отчёт: `.artifacts/local-verification.json`. Локальные тесты на двух моделях устройств не заменяют реальный A → Figma → B → Figma → A.

Применение сохраняет исходные байты/EOL/BOM/encoding/EOF, пропускает одинаковые файлы и не меняет Git index. Конфликт, неизвестная база, неподдерживаемая политика и локальные правки после preview блокируют запись. Общая база продвигается по подтверждённому точному результату; получение или расшифровка сами по себе не означают принятия.
