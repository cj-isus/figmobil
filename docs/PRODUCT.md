# Продукт и требования

Дата: 2026-10-20. Пользователь принял прозрачный разрешённый вариант (D-07) и подтвердил разрешение передачи кода через Figma (D-10). По D-11 реализован первый [локальный preview сравнения без плагина](LOCAL-COMPONENT.md); его полная UI-приёмка открыта. Описанные ниже импорт, экспорт и шифрование относятся к будущему MVP. Конкретные инструменты переноса уточняются в P1. Целевая ОС обоих ноутбуков — Windows. Идентификаторы требований и проверки — в [spec/project.json](../spec/project.json).

## Исходная задача и границы

На ноутбуке A находится проект с local/origin Git; Git remotes и почта для переноса недоступны по условиям пользователя. На ноутбуке B ограничения отсутствуют. Доступна Figma Desktop на A; разрешение конкретных дополнительных установок требуется уточнять. Обе ОС — Windows; версии, объём файлов, политика плагинов и возможность работы с локальным приложением уточняются.

Нужно сохранить полезную часть задачи: конфиденциальность разрешённого обмена, точность восстановления кода, удобство работы и предсказуемое поведение при ошибках. Маскировка назначения и обход контроля в предлагаемую реализацию не входят. Быстрое удаление объекта Figma не является подтверждением уничтожения данных.

Канал «только Figma» выбран пользователем. Предлагается [видимая ручная передача зашифрованного пакета](TRANSPORT.md). Её техническая интеграция пока не проверена; согласование канала не доказывает доставку.

## Предлагаемый первый выпуск

По уточнению D-13 основной путь — один собственный каталог проекта на каждом ПК и зашифрованный текст через холст Figma. Каталог другого компьютера в UI не вводится. Incoming получается из принятого пакета, последняя подтверждённая общая база хранится приложением. Текущий comparator с двумя/тремя локальными папками — диагностический этап, не этот пользовательский поток.

Обычно разработка идёт с одной стороны; на другой пользователь самостоятельно делает merge с коллегами и отправляет результат обратно через Figma. Автоматический merge и постоянная синхронизация не нужны. Защита конфликтов остаётся обязательной: правки коллег могут отличать принимающую копию от базы даже при поочерёдной разработке. Путь canvas copy/paste описан в [TRANSPORT](TRANSPORT.md); его интеграция ещё не проверена.

Локальный инструмент с понятным названием «figmobil — пакеты проекта». На каждом ноутбуке доступны экспорт и импорт: пользователь выбирает разрешённый проект и файлы, проверяет состав пакета и получателя, создаёт пакет; принимающая сторона сначала проверяет его отдельно, затем показывает план применения к выбранной рабочей копии. По D-13 предпочтителен ручной canvas copy/paste шифротекста без плагина; формат/размеры и техническая сохранность ещё требуют прототипа. Прежнее предложение плагина не считается обязательным решением.

По уточнению пользователя **A ↔ B — обязательное требование первого выпуска**, с одинаковой возможностью экспорта/импорта и проверкой конфликтов на обоих ноутбуках. **Обе операции запускаются только отдельными кнопками «Экспорт» и «Импорт».** Постоянная синхронизация, фоновый опрос и наблюдение за файлами исключены. Автоматический merge и оптимизация размера дельтами могут рассматриваться отдельно в рамках явно запущенной операции. Чат в MVP не включён.

По D-15 выдача готового текста ограничена 5 000 000 байт за любые 60 секунд: части не более 250 000 байт с интервалом ≥3с, без burst после простоя. Лимит единый на устройство для всех проектов и направлений. В интерфейсе нужен понятный countdown и отдельное действие для следующей части, без автоматической отправки. Контроль относится к операциям figmobil; повторные ручные вставки ранее выданного текста и внутренний сетевой трафик Figma вне его контроля. Чистая policy и будущая интеграция принимаются раздельно: A-15/A-16, [TRANSPORT](TRANSPORT.md).

## Пользовательские сценарии

До нажатия кнопки система не начинает экспорт или импорт: ни при открытии приложения, ни при изменении файлов, ни при появлении пакета. После завершения выбранной операции она возвращается в ожидание. Внутри запущенного задания проверка, упаковка и прогресс выполняются обычным образом; после перезапуска запись/передача не возобновляется автоматически. Повторный клик во время задания не создаёт дубликат.

Экспорт: выбрать свой локальный профиль → проверить список файлов и исключения → проверить получателя → создать зашифрованный текст → вручную скопировать и вставить в текстовый слой Figma. Состояние «пакет создан» не означает «получатель получил данные». Файловый экспорт пакета может рассматриваться отдельно; он не заменяет основной путь через холст.

Импорт на любом ноутбуке: скопировать содержимое текстового слоя Figma → нажать «Импорт» и вставить текст/все части → проверить пакет отдельно → сравнить с внутренней общей базой и своим локальным проектом → увидеть фактические изменения/конфликты → подтвердить план → повторно проверить, что локальные файлы не изменились → применить только принятые изменения. Первое создание новой копии требует явного выбора пустого локального каталога. История/index/remotes не заменяются. Удаления требуют отдельного явного выбора; конфликт не затирается.

Обратный сценарий: A экспортирует изменения через Figma → B проверяет и применяет → пользователь вручную делает merge с коллегами на B → B экспортирует результат через Figma → A проверяет и применяет. Общая база для следующего обмена — точная версия, принятие которой подтверждено обеими сторонами через тот же канал. Создание, доставка и расшифровка пакета базу не продвигают. После частичного применения/ручного merge MVP удерживает прежнюю базу до точного подтверждения версии; неизвестная или расходящаяся база требует явного разбирательства.

Ошибки: неверный ключ, повреждение, нехватка места, доступ запрещён, отмена, несовместимая версия, повторный импорт. UI сохраняет причину и возможность безопасного повтора; он не отображает успех после частичного результата.

## Что исключается из экспорта

`.git`, `.env*`, приватные ключи, credentials, кэши и сборочные каталоги исключаются по умолчанию. Даже после исключений нужен просмотр человеком: фильтр не доказывает отсутствия секретов. Подключать отдельный scanner можно после выбора инструмента и разрешения установки. Ни сборка, ни package scripts из импортированного проекта автоматически не запускаются.

Рабочая копия изменяется только по подтверждённому плану импорта. История Git, staging/index, remotes и глобальные настройки не меняются; автоматические fetch/pull/push/commit не входят в MVP. Чтение правил `.gitattributes`, EOL и фильтров требуется уже в P1, без автоматического запуска внешних фильтров. Наличие origin не делает перенос файлов автоматически допустимым.

## Чистый Git diff

Требование относится к результату в рабочей копии. Даже если пакет содержит файл целиком, его перенос не должен менять остальные строки. Файлы читаются как байты; для неизменённого содержимого нет повторной записи, перекодирования, нормализации EOL, форматирования, сортировки импортов или добавления финального перевода строки.

Проверяются правила обеих копий: `.gitattributes`, локальные attributes/config, `core.autocrlf`, `core.eol`, encoding/filter/mode. При несовместимости сначала показывается причина; настройки и файлы автоматически не переписываются. Побайтовая распаковка и применение по уже принятой Git-политике — разные проверки. Нельзя обещать одинаковые байты рабочих деревьев при разных checkout-правилах. Подробная матрица — [FILE-FIDELITY](FILE-FIDELITY.md).

## Приёмка и измерения

На синтетическом проекте проверяются пустые/бинарные файлы, Unicode-пути, варианты EOL/BOM/encoding и повторный импорт. Цикл A → B → A без правок не добавляет diff; правка одной строки даёт только ожидаемые изменения в обоих направлениях. Проверяются staged/unstaged правки, конфликт/неизвестная база, отмена, сбой и native checks самого проекта на каждом ноутбуке. Восстановление исходных байтов проверяется отдельно от согласованного представления рабочей копии.

Не обещаем скорость без измерений. На этапе P1 выбираются реалистичные размеры набора и пороги времени/памяти; на P4 фиксируются фактические результаты. Совпадение скриншота или успешный doctor не заменяет проверку операций с файлами.
