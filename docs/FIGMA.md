# Возможности Figma и пределы гарантий

Проверено 2026-10-20 по официальным источникам. Учётная запись, проекты и файлы Figma не открывались и не изменялись. Подтверждённый факт отделён от проектного вывода; измерений на двух ноутбуках пока нет.

| Подтверждённый факт | Значение для решения | Источник |
|---|---|---|
| Plugin API читает и изменяет содержимое редактора; запуск инициируется пользователем. Фоновые плагины не поддерживаются, одновременно работает один плагин. | Обычный плагин не является постоянно действующей службой. Это не запрещает работу во время открытой plugin session. | [Plugin API](https://developers.figma.com/docs/plugins/) |
| Пользователь может остановить плагин; плагин с UI прекращается при закрытии соответствующей вкладки. | Отключение получателя нужно считать нормальным состоянием. | [How Plugins Run](https://developers.figma.com/docs/plugins/how-plugins-run/) |
| Files REST API предоставляет JSON/изображения файлов и узлов. | Нельзя рассчитывать на универсальный REST endpoint редактирования текстовых слоёв. Отдельные API, например comments/variables, имеют свои функции. | [Files endpoints](https://developers.figma.com/docs/rest-api/file-endpoints/) |
| Comments API создаёт и удаляет комментарии; удаление разрешено автору комментария. | Возможность удаления зависит от пользователя. Это не гарантия удаления всех серверных копий. | [Comments endpoints](https://developers.figma.com/docs/rest-api/comments-endpoints/) |
| `clientStorage` локален, не синхронизируется между пользователями, ограничен 5 MB и может исчезнуть при очистке кэша. | Это восстанавливаемые настройки, а не транспорт или гарантированное хранилище ключей. | [clientStorage](https://developers.figma.com/docs/plugins/api/figma-clientStorage/) |
| Сеть плагина ограничивается manifest `allowedDomains`, CSP и CORS; домены раскрываются пользователям. | Возможность подключения интеграции требует проверки в разрешённой среде. | [Network requests](https://developers.figma.com/docs/plugins/making-network-requests/) |
| REST квоты зависят от seat, плана ресурса и endpoint; есть 429 и `Retry-After`. | Фиксированную низкую задержку частым опросом обещать нельзя. | [Rate limits](https://developers.figma.com/docs/rest-api/rate-limits/) |
| `FILE_UPDATE` webhook отправляется в пределах 30 минут бездействия редактирования. Есть отдельный `FILE_COMMENT`. | `FILE_UPDATE` не даёт мгновенную доставку правок. | [Webhook events](https://developers.figma.com/docs/rest-api/webhooks-events/) |
| У документа есть checkpoints; Delete Version Info убирает сведения версии, но не её содержимое. Удалённые комментарии через историю версий не восстанавливаются. | Удалённый слой мог сохраниться в версии. Нельзя утверждать, что каждый удалённый комментарий хранится именно в version history. | [Version history](https://help.figma.com/hc/en-us/articles/360038006754-View-a-file-s-version-history) |
| Organization/Enterprise предоставляют администраторам activity logs; в них бывают пользователь, время и IP. | Шифрование содержимого не делает активность невидимой. Источник не доказывает регистрацию каждого сообщения/запуска плагина. | [Activity logs](https://help.figma.com/hc/en-us/articles/360040449533-View-and-export-activity-logs) |

Общий предел вывода: [privacy policy Figma](https://www.figma.com/legal/privacy/) допускает удержание определённых данных, в том числе в backup archives. Это не доказательство конкретного срока хранения удалённого ciphertext. Нельзя обещать ни уничтожение всех копий, ни отсутствие следов по факту удаления объекта из UI.

## Что ещё неизвестно

- Разрешены ли разработческие/частные плагины на первом ноутбуке и в нужной организации.
- Какие аккаунты, планы и права на файлы доступны на обоих устройствах.
- Пользователь подтвердил разрешение переноса кода через Figma (D-10); осталось проверить технический путь [TRANSPORT](TRANSPORT.md), а не спрашивать канал заново.
- Реальная задержка, поведение при offline, пригодный размер и ограничения устройств.

Проверять интеграцию следует только после согласования её прозрачного назначения и конкретного инструмента. Для исследования UI/синхронизации достаточно синтетических статусов; исходники и ключи не нужны. Протокол скрытого обмена и алгоритмы удаления следов здесь не описываются.
