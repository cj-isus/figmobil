- D-14/D-16: пользователь разрешил локальную реализацию с готовой Go-библиотекой age, Ed25519, Windows DPAPI и синтетическими испытаниями. Старый запрет P2T изменён этим согласованием, P1/P4 не закрыты.

- Только явные кнопки, без watchers/polling, фоновой отправки или автоматического возобновления. Дополнительные установки на первом ноутбуке по-прежнему согласовываются отдельно; для текущей версии новых установок на целевые устройства не было.

## Что реализовано

`dist/figmobil.exe` — Windows x64 приложение с встроенным HTML/CSS/JS и лицензиями зависимостей. Использует существующий браузер, случайный IPv4 loopback-порт, ключ текущего сеанса, проверки Host/Origin и один владеющий процесс на устройстве. Не требует целевых Go/Node/age.exe/Wails/WebView2 или Figma-плагина. Git используется только для чтения политики и режимов index, не для передачи.

Основной мастер: приглашение → ответ через Figma → сверка кода непосредственно на обоих экранах → обмен подтверждениями. Настройка ключей не объявляет файловые копии одинаковыми. Экспорт создаёт полный снимок выбранного состава; выдача каждой части отдельная. Импорт проверяет части, полный шифротекст, отправителя и manifest до предпросмотра. Рабочая папка меняется только по отдельно подтверждённому плану.

Общая база продвигается по точному подтверждённому снимку. Конфликт, устаревший план и несовместимая политика Git блокируют запись. Сохранённые несвязанные локальные правки или ручное слияние требуют обратной отправки фактического результата, без ложного подтверждения исходного пакета. Удаление требует явного списка путей; отсутствие файла само по себе ничего не удаляет. Диагностическое сравнение нескольких локальных папок сохранено в раскрываемом разделе.

Криптография: age X25519 для конфиденциальности и Ed25519 для аутентификации, с привязкой обоих полных наборов ключей, ролей, проекта и версии. Секретные ключи и локальные пакеты/состояние защищены DPAPI CurrentUser в `%LOCALAPPDATA%\figmobil`, отдельно от проекта. Закреплены `go.mod`/`go.sum`; исходники и BSD-лицензии зависимостей просмотрены. Независимая проверка публичного checksumDB не завершена из-за TLS/существующего proxy; локальное `go mod verify` не выдаётся за неё. Подробности: [DEPENDENCIES](../internal/secure/DEPENDENCIES.md), `internal/secure/dependency-verification.json`.

Windows-применение готовит новую копию, использует операции относительно удерживаемых каталогов и проверяемый журнал восстановления. Нетронутые файлы не переписываются. Проверяются текущие хеши, коллизии путей, reparse/8.3 aliases, hardlink и права. Именованные ADS у изменяемого назначения блокируют запись до изменения namespace. `.git`, index и config не переносятся и не меняются. Подробности — [FILE-FIDELITY](FILE-FIDELITY.md).

- `node scripts/project/verify.mjs`: **10/10 PASS**. Обвязка, 13 регрессий проверяющего инструмента, 32 теста моделей/контроллеров UI, gofmt, все Go tests, vet и сборка текущего Windows exe. Отчёт: `.artifacts/local-verification.json`.
- Две независимые локальные модели устройств используют настоящие age/подписи/DPAPI и файловую систему. Проверены настройка пары, A → B → A, перезапуск состояния, повтор/повреждение/смешивание частей, чужой отправитель, неверный код, конфликт, поздняя правка, сброс с повторным импортом, ручное слияние и точный ACK. Gate в сквозных сценариях заменён управляемым допуском без ожиданий; настоящий gate имеет отдельные детерминированные проверки.
- `TestEncryptedChannelPreservesOrdinaryGitDiffAndStaging`: на синтетических Git-копиях цикл без правок не создаёт diff; правка одной CRLF-строки даёт ровно 1 добавление/1 удаление. Сохранены index, staged/unstaged правки другой стороны, байты и mtime нетронутого UTF-16 файла; обратный результат согласован.
- Настоящие Windows-проверки: CurrentUser DPAPI, блокировка второго процесса, hardlink-race, reparse, 8.3 aliases, protected/inherited DACL, именованные ADS, конкурентное появление файла и явное восстановление. Исправлен writer после обнаруженной гонки in-place записи; итоговый полный прогон выполнен уже на новой реализации.
- HTTP-тесты используют настоящий Manager/DPAPI и обработчик без listener: auth/Origin/Host, неизвестные поля, предел тела, начальный rate-limit без выдачи текста, неизменные счётчики и allowlist ресурсов.
- Независимые ревью крипто/файловой границы и состояния протокола приняты в просмотренном объёме. Ответ ревьюера не заменяет перечисленные тесты; итоги — `.artifacts/channel-review.md`.

UI-тесты используют DOM-модель, а не настоящий браузер. Ранее проверенный в браузере старый comparator не подтверждает новый мастер. Повторное подключение к локальной странице отклонено политикой браузерного инструмента; обход не выполнялся. Preview-процесс не работает. Настоящая Figma не использовалась для испытаний.

## Ограничения и следующий шаг

1. Пройти ручной браузерный сценарий по [QUALITY](QUALITY.md): формы, состояния, клавиатура/фокус, clipboard и размеры экрана. A-13/P2/P3 остаются открытыми.
2. P1/Q-03/Q-04: подтвердить Windows/архитектуру/Figma Desktop на обоих устройствах, разрешённость запуска exe, фактический состав, исключения и Git-политику. Текущая сборка проверена только на Windows x64 машины разработки.
3. На синтетических файлах выполнить реальный A → Figma → B → Figma → A: копировать содержимое текстового слоя, проверить вместимость/побайтовую сохранность, части, повторы, неполноту, конфликты и обычный Git diff. Это P4; его успех пока не установлен.
4. Проверить производительность на согласованном составе. Снимок полный, не delta; пределы чтения — 5 000 файлов, 8 МиБ/файл, 32 МиБ исходных байтов. Локальное защищённое состояние ограничено; переписывание больших пакетов при добавлении частей ещё не измерено. Автоматического исключения больших файлов нет.

MVP поддерживает обычные Windows-файлы и политику Git без преобразований checkout. Executable/symlink/gitlink, unmerged index, filters/encoding/EOL-преобразования и неизвестные правила отклоняются; настройки Git не исправляются автоматически. ADS не передаются как возможность.

Применение не является атомарной транзакцией или гарантией восстановления при отключении питания. DPAPI защищает journal/blob в состоянии приложения; временные `.figmobil-new-*`/`.figmobil-old-*` в рабочем каталоге содержат открытые данные с проверенными правами. После завершения удаляются, secure erase не обещается. При неизвестной новой версии восстановление останавливается, сохраняя её для явного разрешения.
