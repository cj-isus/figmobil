# Критерии качества разработки

Требование пользователя «пиши проект максимально качественно» задаёт проверяемую готовность каждого компонента. Это порядок будущей реализации разрешённого объёма, а не подтверждение работы приложения. Требование R-13 и итоговая приёмка A-11 находятся в [реестре](../spec/project.json).

## До реализации компонента

- Определить ответственность, входы, результат, ошибки и затрагиваемые критерии приёмки. Сначала искать пригодную реализацию в проекте и готовых инструментах.
- Выбрать минимальную структуру под реальную задачу. UI, доменные правила и системные операции имеют отдельные границы; пустые слои и универсальные движки заранее не создаются.
- Выбранная схема данных служит источником типов и проверки внешнего ввода. Версии форматов и неизвестные значения обрабатываются явно. Изменение контракта сопровождается решением о совместимости.
- Проверить ограничения среды до выбора зависимости. Фиксировать версии и происхождение; конкретные установки на первом ноутбуке предварительно уточнять.

## Условия готовности компонента

| Область | Необходимое доказательство |
|---|---|
| Поведение | Проверены основной сценарий и существенные ошибки; критерии связаны с конкретными тестами или воспроизводимой ручной проверкой |
| Контракты | Некорректный внешний ввод даёт предусмотренный результат; ошибки имеют стабильные коды и понятное пользователю описание |
| Сохранность | Для операций с файлами выполнены соответствующие случаи [FILE-FIDELITY](FILE-FIDELITY.md); успешное копирование не заменяет проверку обычного Git diff |
| Сбои | Для изменяющих состояние операций проверены отмена, повторный вызов, изменение данных после предпросмотра и восстановление после прерывания |
| Интерфейс | Проверены пустое состояние, ожидание, ошибка, завершение, клавиатура, фокус и повторное нажатие; в простое операции не запускаются |
| Интеграция | Сквозная проверка использует реальные затронутые компоненты; подмена файлового слоя не доказывает работу с диском |
| Анализ кода | Пройдены применимые проверки выбранного стека; подавление ошибки требует объяснения, а не добавления `any`, ignore или отключения проверки ради зелёного отчёта |
| Ревью | Для записи файлов, изменения контрактов и других существенных рисков проведено независимое ревью; найденные проблемы исправлены и перепроверены либо явно оставлены открытыми |

Проверки выбираются по изменённому поведению и риску. После исправления дефекта нужен тест прежнего сбоя, когда его можно воспроизвести автоматически. Не требуется тест на каждый вспомогательный метод, повторение реализации в тестах или произвольный процент покрытия. После успешных проверок неизменённый код повторно не проверяется без причины.

## Доказательства и готовность выпуска

Отчёт по компоненту содержит идентификаторы приёмки, проверенную версию кода, команду или сценарий, среду, результат и известные ограничения. Статусы «не запускалось», «ошибка» и «пройдено» различаются. Старый результат не переносится на затронутое новой правкой поведение.

Локальные unit-тесты, интеграция на одном компьютере и проверка на двух ноутбуках — разные доказательства. Приложение готово к заявленному сценарию только после соответствующей приёмки P4; до неё нельзя обещать чистый Git diff и корректную сборку на обоих устройствах.

Производительность оценивается на согласованных размерах проектов с записью времени и потребления ресурсов. Обещания «мгновенно» и универсальные пороги без измерений не используются. В отчёты не включаются ключи, исходники и секреты.

Для локального preview доступна общая команда проверок и сборки:

```powershell
node scripts/project/verify.mjs
```

Она выполняет проверки обвязки, тесты модели UI, Go tests/vet/format и сборку Windows exe. Область результатов — локальный компонент и синтетические данные. Дополнительные команды для обвязки:

```powershell
node scripts/project/check.mjs
node --test scripts/project/check.test.mjs
```

Наличие собранного exe и автоматических PASS не заменяет ручную приёмку UI или будущий цикл переноса на двух ноутбуках. Настоящий документ не снимает открытые вопросы [плана](PLAN.md).
