# Память и завершение работы

Описание глобального механизма и его первоначальной проверки в `codex-harness-demo`. Команды установки и `.artifacts` относятся к исходному комплекту; фактическое состояние целевого проекта — его README и docs/STATE.md. Не считать перечисленные здесь результаты проверками приложения целевого проекта.

Три совместимых уровня:

- **Native Codex Memories**: встроенное асинхронное извлечение опыта из подходящих локальных чатов. Включены generation/use, окно источников 90 дней, idle от 1 часа, до 8 rollout за запуск и защита остатка квоты 25%. Фоновая работа модели расходует квоту; это не мгновенное сохранение каждого сообщения.
- **Checkpoint чата**: локальный JSON с целью, незавершённым, критериями, проверками, решениями и следующим шагом. Не вызывает модели. Для Git путь `$CODEX_HOME/project-memory/_sessions/<hash Git common dir>/threads/<session>.json`: тот же чат сохраняет задачу при handoff в другой worktree. Для папки без Git — `<hash canonical project>/threads/<session>.json`. Разные чаты изолированы; общие уроки остаются отдельно для каждого worktree. Изменения рабочего дерева требуют повторной проверки фактов. Атомарная запись, locks и обязательная revision после первого checkpoint защищают от перезаписи.
- **Память проекта**: существующие AGENTS, LESSONS, ADR, общий STATE и проверенные факты sidecar с источником. Recall выбирает собственный checkpoint и релевантные записи, ограничивает размер, помечает их как данные. Устаревшие факты можно supersede. После 100 записей нужна осознанная консолидация; автоматического удаления уроков нет.

MCP — транспорт, а не алгоритм памяти. Отдельный memory MCP и векторная БД здесь пока не нужны: native memory, файлы и выборочный recall дают восстановление без дополнительного сервиса. Это инженерный выбор, не универсальный победитель benchmark. На больших объёмах следует измерять retrieval и необходимость серверного хранилища.

## Автоматическое подключение

`node scripts/setup-memory.mjs` показывает план; `--apply` устанавливает стабильные скрипты и skill в пользовательский Codex home, сливает hooks.json и добавляет fallback в глобальный AGENTS.md. Чужие настройки сохраняются; конфликт управляемых файлов останавливает запись. Приложения проектов не изменяются.

- SessionStart: инициализация нового ID, восстановление **собственного** ledger при resume/compact. Fork получает отдельный ID и не импортирует автоматически обязательства родителя.
- UserPromptSubmit: релевантный контекст; одинаковый пакет повторно не добавляется.
- Stop: одна попытка вернуть агента к active-задаче. Повторный Stop только сообщает о незавершённом. Явный blocked с next позволяет честно запросить ресурс. Простые ответы без цели не блокируются.
- Workers возвращают результаты родителю и не пишут его ledger.

**При отсутствии доверия нужен один шаг в интерфейсе:** `/hooks` → просмотреть и доверить три обработчика. Codex требует доверия к точному определению; новые или изменённые определения требуют повторного просмотра. Установленные файлы, записи trusted_hash и прямой запуск hook в тесте не доказывают фактическое получение пакета работающим Desktop. Защита не обходится. Fallback позволяет агенту вызвать recall, если hook-пакет отсутствует.

## Восстановление после сжатия

`SessionStart` с `source: compact` выполняется перед следующим запросом к модели,
в том числе при сжатии посреди хода. Это штатный механизм Codex, а не отключение
сжатия: [официальные hooks](https://learn.chatgpt.com/docs/hooks#sessionstart).

Пакет памяти содержит recovery-envelope: canonical project, session ID, revision,
количество полей/записей, признак усечения и точную команду полного status.
Сначала передаются constraints, next и открытые обязательства; optional facts —
после них. При недостатке бюджета нельзя считать обрезанный пакет полным:
агент обязан загрузить полный status перед дальнейшей работой.

Если чат запущен из общей папки, а задача относится к другому проекту:

```powershell
node "$env:USERPROFILE/.codex/harness/project-memory.mjs" bind --cwd <cwd-чата> --project <проект> --session $env:CODEX_THREAD_ID
```

Binding привязан к реальному ID, проверяет origin и target и не переносит ledger.
Повторное изменение требует revision. CLI recall/status не перенаправляются:
для них cwd всегда указан явно. Новый fork не получает binding родителя;
перенос scope выполняется явно с provenance и известным родительским ID.
Binding не изменяет рабочую папку в UI и не даёт новых разрешений на файлы.

Сохранять checkpoint до реализации, после значимого шага, перед переключением
темы и передачей работы. Hooks не способны восстановить факт, который агент
не записал. Native Memories обновляются асинхронно и не заменяют ledger активной
задачи: [официальная память Codex](https://learn.chatgpt.com/docs/customization/memories).

## Существующие чаты

`node scripts/harness/native-memory.mjs --configure-defaults --apply-existing --out .artifacts/native-memory-enable.json` использует public app-server RPC, не запускает задачи и не читает transcript. Подтверждены ACK для 8 неархивных сохранённых локальных чатов; 7 архивных явно пропущены: установленный setter возвращает thread-not-found. После восстановления нужного архивного чата команду можно повторить. Sidecar создаётся при следующем входе/запросе с cwd/session ID; история целиком не импортируется.

Локальная установка не меняет память облачного ChatGPT. ACK не доказывает, что работающий Desktop перечитал настройки или что native extraction уже состоялось. Для надёжной загрузки новых глобальных настроек перезапустить приложение. Не обещаем немедленное воспоминание о всей истории.

## Против недоделок

Skill project-memory: восстановить → сохранить цель и критерии → реализовать и проверять → обновить незакрытое → сверить весь запрос → завершить с доказательствами. Побочный вопрос не отменяет основную задачу. При установке core-профиля skill переносится вместе с модулем памяти.

Для бага: воспроизведение и гипотеза причины → минимальное исправление → проверка исходного сбоя и ближайшей регрессии. Для UI оцениваются затронутые loading/empty/error/success, клавиатура, размеры; для SQL — null, ошибки, контракты, миграции. Это анализ риска, не огромный обязательный checklist на любую правку.

complete отклоняется без цели/критериев/проверок, при openTasks, open/failed acceptance, failed/not_run checks и отсутствии evidence/detail. waived требует конкретной причины. Валидатор проверяет **структуру**, а не истинность доказательств; агент обязан реально проверять результат. Память и большой контекст не гарантируют, что ИИ никогда не забудет или не ошибётся.

Частичный checkpoint сохраняет пропущенные поля, а не обнуляет прежние обязательства; старый revision отклоняется. Критические границы хранятся отдельно в constraints; неизвестные поля отклоняются. Новая цель требует явных актуальных критериев и проверок: старые PASS не подходят новой задаче. Отменённый пользователем объём отмечается решением с причиной, а не тихо исчезает.

## Проверка и обслуживание

`npm run check`: тесты восстановления, изоляции проектов/чатов/worktrees, конкурентных записей, revision conflict, superseded фактов, редакции секретов, ограничений размера, symlink/junction, сохранности фактов, Stop без циклов и установки без порчи чужих файлов.

Редакция секретов эвристическая: не сохранять их намеренно. После аварии может остаться lock; writer выдаёт memory-lock-busy и не удаляет чужой lock автоматически. Перед ручным удалением конкретного lock убедиться, что writer отсутствует. Recall не исполняет текст и не обращается к сети.

Официальные источники: [Codex Memories](https://learn.chatgpt.com/docs/customization/memories), [lifecycle hooks и доверие](https://learn.chatgpt.com/docs/hooks). Реальное применение: `.artifacts/native-memory-enable.json`. Пути установки показывает dry-run setup-memory.
