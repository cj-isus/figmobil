# База для новых проектов

Глобальное правило в `$CODEX_HOME/AGENTS.md` предлагает обвязку в первом содержательном чате кодового проекта. Это инструкция агенту, не расширение окна New Project. Оно действует в локальном Codex, загружающем этот AGENTS; не устанавливает настройки в облачные исполнители, Claude или Cursor. Для уже активного старого чата начало нового запуска/turn должно загрузить инструкции; доставка на каждом Desktop-пути отдельно не аттестована.

Перед вопросом используется установленный CLI:

```powershell
node C:/Users/Пользо/.codex/harness/project-onboarding.mjs claim --cwd <корень-проекта> --session $env:CODEX_THREAD_ID
```

Фактический корень определяют из задачи и `project-memory resolve/bind`, а не из случайного cwd общего чата. Для Git используется корень checkout; отдельные worktrees имеют отдельный выбор, потому что их конфигурации могут отличаться. Для non-Git передают явный корень. Subagents не показывают предложение.

При `ask=true` агент задаёт один вопрос через доступный инструмент вопросов или обычный диалог: **«Собрать обвязку под этот проект: память, правила, проверки и подходящие готовые skills?»**

| Ответ | Значение CLI | Дальнейшее поведение |
|---|---|---|
| Да, подобрать и настроить | yes | Исследовать проект и собрать уместный профиль |
| Позже | later | Подавить повторные предложения до явного пересмотра |
| Без обвязки | no | Продолжать обычную работу без настройки |

```powershell
node C:/Users/Пользо/.codex/harness/project-onboarding.mjs decide --cwd <корень-проекта> --session $env:CODEX_THREAD_ID --decision yes --token <token-из-claim>
```

Выбор хранится вне репозитория: `$CODEX_HOME/harness/onboarding/<projectKey>.json`. Отказ не создаёт файлов в проекте. На одно предложение выдаётся lease 30 минут; параллельный чат видит pending и не спрашивает повторно. Истечение lease позволяет повторно предложить настройку, **не означает согласие**. Просроченный token требует нового claim перед сохранением ответа. Повторный claim владельца до истечения возвращает token, но `ask=false`: не задавай тот же вопрос снова после compaction. Незавершённое yes разрешает продолжить настройку; не означает, что она выполнена.

Имеющаяся обвязка определяется по согласованным маркерам и ключевым файлам: configured не зависит от голословного yes. `medok` и исходный demo распознаются без нового вопроса. Чужие системы с другими маркерами могут потребовать ручной проверки; не заменяй их слепо.

Явный запрос «собери обвязку» уже даёт yes — повторный вопрос не нужен. Если пользователь пересмотрел earlier/later/no, выполни `reopen --cwd ... --session ...`, затем claim и сохрани его прямое решение. Reopen сам не даёт согласия. Активный pending другого чата не перехватывай. `status` читает состояние без записи.

После yes — skill `project-harness`: manifests/lockfile/CI → реальные архитектура и reuse → ограничения и критерии → минимальный core → релевантные навыки из каталога → поиск недостающих по первоисточникам → аудит исходников и pin → статические и native проверки → checkpoint/evidence. Известный каталог — `docs/SKILLS-CATALOG.md`; библиотека адаптаций находится в исходном комплекте `.harness/skills-library/`. Не копировать специфичные пути/версии/команды medok в другой проект без сверки. Сам факт согласия на обвязку не разрешает внешние API-вызовы, платные запуски или произвольные production-операции.

Установка глобального правила повторяема: `node scripts/setup-memory.mjs`, затем `--apply`. Скрипт сохраняет существующие правила, конфликтует при ручном изменении управляемых блоков и не меняет команды/trust hooks, модель или разрешения. Новый проект не запускает скачанные установщики: новые skills сначала изучаются, затем устанавливается только выбранное.
