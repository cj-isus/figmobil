# План компонентной разработки

Источник идентификаторов и статусов — [spec/project.json](../spec/project.json). Прозрачное назначение согласовано по A-00, канал Figma — по A-12. P1 остаётся открытым; независимый P2 реализован как локальный preview, полная ручная UI-приёмка ещё открыта. Эти решения не доказывают работу транспорта.

Каждый компонент принимается по [критериям качества](QUALITY.md): контракт, поведение, существенные ошибки, интеграция и ревью по риску. A-11 проверяет полноту доказательств перед завершением P4.

## Порядок P2 и P2T

P1 начат после согласования назначения A-00. Канал Figma выбран по A-12/D-10. Инструменты/установки и детали целевой среды (A-06/Q-03/Q-04) закрываются в ходе P1; они блокируют P2T. По D-11 отдельно разрешён первый локальный компонент P2 без плагина и новых зависимостей: [сравнение копий](LOCAL-COMPONENT.md). Он зависит от P0, ничего не записывает и не реализует канал передачи. Выбор и чтение документации не означают разрешения установки.

Сначала контракт профиля, файлов, общей базовой версии и сохранности представления, затем побайтовый снимок. После выбора готового инструмента — crypto adapter и roundtrip. Далее inspection, сравнение трёх состояний base/incoming/local, план конфликтов и выборочное применение с повторной проверкой локального состояния. Каждый шаг проверяется в обоих направлениях; публичный API не меняется незаметно при появлении UI.

Двусторонняя работа обязательна уже в MVP, только по отдельным кнопкам. Постоянная синхронизация, фоновый опрос и file watchers исключены. Оптимизация размера дельтами и автоматический merge остаются отдельными будущими задачами внутри явно запущенной операции. Удаления не выводятся из отсутствия файла в выбранном экспорте; они требуют явного действия и проверки базы.

По D-13 основной сценарий — поочерёдная разработка, ручной merge с коллегами и обратный пакет через Figma. Incoming/base внутренние; пользователь выбирает один собственный каталог на каждом ПК. Canvas copy/paste без плагина — предпочтительный прототип для P1, ещё без доказательства доставки. A-14 проверяет этот пользовательский путь; A-13 относится только к диагностическому comparator.

## Порядок P3

Определить визуальный контракт, затем реализовать общие элементы выбора/статуса/ошибки. Собрать ProjectSelector, FileSelectionPreview, RecipientSelector, ExportPanel, ImportPreview, JobProgress и ResultReport по мере появления реального поведения; названия предварительные. Не создавать отдельный компонент для каждого фрагмента разметки.

Состояния empty/loading/error/success, доступная клавиатурная навигация и отмена входят в функциональную приёмку. Из «ФРОНТОВОЙ» выборочно подключить design-contract, capture/compare и visual-triage после появления утверждённого UI. Дифф изображения — диагностика, а не автоматическая замена содержательной приёмки порогом 0.98.

A-10 проверяет отдельные кнопки на A и B, отсутствие автозапуска при открытии/изменении файлов/появлении пакета/перезапуске, отсутствие фоновых наблюдателей и защиту от повторного клика активного задания.

## Проверки по риску

- Обвязка сейчас: валидность и ссылки JSON, зависимости этапов, approval gate, целостность managed-файлов, существование документов, Node syntax, doctor.
- Ядро позже: synthetic fixtures с опасными путями, Unicode, бинарными/пустыми файлами, коллизиями, повреждением, неверным ключом и матрицей [FILE-FIDELITY](FILE-FIDELITY.md).
- Запись позже: отмена, конфликт, незакоммиченные/staged правки, изменение после preview, прерывание процесса и повторный импорт; неизменённые файлы не записываются.
- UI позже: подтверждённый путь от выбора до отчёта, без замены файлового слоя mock при итоговом end-to-end тесте.
- Два ноутбука позже: цикл A → B → A без правок и с однострочными правками в каждом направлении, обычный Git diff без подавления пробелов/EOL, native checks проекта на обоих, выбранные размеры и измеренное время.

Перед новым этапом сверить ограничения и открытые решения. После значимого шага обновлять project-memory и общий STATE; старые PASS нельзя переносить на изменённую цель. Полное качество приложения не подтверждается успешным check обвязки.
