# Memory Loop — память опыта между сессиями

Код и артефакты живут в git, но «почему мы сделали так» и «что уже пробовали»
агент при следующем запуске не знает. Этот протокол делает опыт переносимым.

## Хранилища

Текущая задача хранится отдельно от уроков: skill `project-memory` ведёт изолированный checkpoint чата в глобальном sidecar. При hook-пакете не повторяй полный recall. `docs/STATE.md` остаётся общим обзором. Native Codex Memories — дополнительное асинхронное воспоминание, а не гарантия сохранности незакрытых обязательств; сгенерированные файлы вручную не менять.

| Уровень | Файл | Что хранить | Жизненный цикл |
|---|---|---|---|
| 1. Правила | `AGENTS.md` | стабильные, проверенные правила (лимит проекта ≤200 строк) | медленно, через дистилляцию |
| 2. Опыт | `docs/LESSONS.md` | сырые уроки: ошибка → исправление, отвергнутые подходы, находки | append; дистилляция в уровень 1 |

## Когда ЗАПИСЫВАТЬ (в docs/LESSONS.md)

1. **Ошибка исправлена** → одна строка: контекст, что было не так, правило.
2. **Пользователь поправил** → записать поправку как правило (это его волевое
   решение, а не твоя догадка).
3. **Подход отвергнут** → чтобы не предлагать его снова в следующий раз.
4. **Удачная находка** → рабочая команда/файл/приём, найденный поиском.

Формат записи (одна строка):
```
- [2026-10-12] <область>: <факт/ошибка> → <правило>
```

НЕ записывать: статус текущей задачи (это не память), секреты, то, что агент
выводит из кода сам (структура, команды — это MAP/package.json).

## Когда ЧИТАТЬ

- В начале задачи в знакомом проекте: **grep по теме** в docs/LESSONS.md
  (не читать файл целиком, если он большой — это и есть экономия контекста).
- Перед повторением ранее отвергнутого подхода — обязан прочитать.
- Перед правками AGENTS.md — чтобы не создать дубль существующего правила.

## Дистилляция (уровень 2 → уровень 1)

Триггеры:
- одно правило подтвердилось **дважды** (повторная ситуация) → стабильно;
- `docs/LESSONS.md` превысил **~50 строк** → обрезка;
- правило касается ВСЕХ задач проекта, а не одной области.

Действия:
1. Перенести стабильное правило в `AGENTS.md` одной строкой (imperative).
2. Удалить дубли из LESSONS.md (оставить дату первой записи).
3. Следить за лимитом AGENTS.md ≤200 строк: если перерос — удалить
   всё, что и так гарантируется линтером/кодом;
   процедуры → в скилл; длинные разъяснения → в docs/.

## Проверка памяти (перед финалом задачи)

- [ ] Была ошибка/поправка → строка в LESSONS.md есть?
- [ ] LESSONS.md не перерос дистилляцию?
- [ ] Правило из опыта не противоречит AGENTS.md/линтеру (конфликт → решить, не плодить)?

## Экономия контекста

- Память читается точечно (grep), не дампом.
- Новые уроки добавлять; при дистилляции разрешено объединять записи,
  удалять дубли и переносить стабильные правила в AGENTS.md. Сохранять
  существенный контекст и дату первого наблюдения, не переписывать историю ошибки.
- Правило живёт в одном месте: дубли между LESSONS/AGENTS/README запрещены
  (несколько источников истины = расхождения).
